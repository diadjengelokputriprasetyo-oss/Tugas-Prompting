## 1. UC-01: Menjalankan Peramalan Permintaan Suku Cadang Bulanan berbasis AI ★

* **ID & Nama Use Case:** UC-01 Menjalankan Peramalan Permintaan Suku Cadang Bulanan
* **Aktor Utama:** Manager Persediaan (Pak Budi)[cite: 1]
* **Aktor Pendukung:** 
  * Backend AI Inference Engine (Layanan/Modul Model ML KNN & SVM Hybrid)[cite: 1]
  * Database System (PostgreSQL)
* **Kaitan ke ID User Story & FR:** US-02, US-03, US-06, US-04 | FR-02, FR-03, FR-04, FR-06[cite: 1]

### Preconditions
1. Manager Persediaan telah berhasil *login* dan masuk ke halaman modul Peramalan.
2. Data transaksi histori penjualan suku cadang bulanan (minimal 12–24 periode bulan) telah berhasil diunggah dan terverifikasi di Database[cite: 1].

### Postconditions
1. Sistem menampilkan hasil angka peramalan kuantitas suku cadang bulan depan ($\hat{Y}_{t+1}$) beserta estimasi *safety stock*[cite: 1].
2. Hasil peramalan tersimpan ke dalam database log prediksi.

### Alur Utama (Main Flow)
1. Manager Persediaan memilih kode/kategori suku cadang dan metode peramalan yang diinginkan (KNN Standar / Hybrid SVM-KNN)[cite: 1].
2. Manager Persediaan menekan tombol untuk memicu eksekusi peramalan[cite: 1].
3. Sistem mengambil data transaksi histori suku cadang terkait dari Database.
4. Sistem melakukan ekstraksi *feature engineering* membentuk vektor *Lag 1, Lag 2, Lag 3* dan *Moving Standard Deviation*[cite: 1].
5. Sistem mengirimkan matriks vektor fitur ke Backend AI Inference Engine[cite: 1].
6. Backend AI Inference Engine menghitung nilai prediksi kuantitas permintaan menggunakan model terlatih[cite: 1].
7. Backend AI Inference Engine mengembalikan nilai prediksi kuantitas dan interval estimasi eror ke sistem[cite: 1].
8. Sistem menghitung rekomendasi *safety stock* berbasis standar deviasi dan *lead time*[cite: 1].
9. Sistem menerapkan aturan bisnis *guardrail*: membulatkan nilai negatif menjadi `0` dan melakukan pembulatan ke atas (*ceiling*) untuk unit suku cadang[cite: 1].
10. Sistem menampilkan hasil kuantitas peramalan, *safety stock*, dan grafik tren di layar[cite: 1].
11. Sistem menyimpan riwayat hasil prediksi ke Database.

### Alur Alternatif (Alternative Flow)
* **AF-01: Pengguna Memilih Model Lanjutan Hybrid (SVM + KNN)**
  * Pada langkah 1, pengguna memilih metode "Hybrid Ensemble"[cite: 1].
  * Pada langkah 6, Backend AI Inference Engine memproses prediksi menggunakan kombinasi bobot model SVM dan KNN[cite: 1].
  * Alur kembali ke langkah 7.

### Alur Eksepsi Khusus AI (AI Exception Flows)

* **EX-01: Data Histori Kurang / Kualitas Data Rendah (Sparse/Insufficient Data)**
  * *Kondisi:* Data histori transaksi kurang dari 3 bulan (vektor *Lag 1, 2, 3* tidak lengkap)[cite: 1].
  * 1. On langkah 4, sistem mendeteksi bahwa jumlah deret waktu tidak memenuhi syarat minimum fitur *lag*[cite: 1].
  * 2. Sistem membatalkan pengiriman ke AI Inference Engine.
  * 3. Sistem menampilkan pesan peringatan: *"Data histori penjualan kurang dari 3 bulan. Peramalan AI tidak dapat dijalankan."*[cite: 1]
  * 4. Sistem mengaktifkan *fallback mode*: Menghitung prediksi menggunakan rata-rata bergerak sederhana (*Simple Moving Average*)[cite: 1].

* **EX-02: Timeout atau Gagal Koneksi ke Engine AI (NFR-02 & NFR-07 Violation)**
  * *Kondisi:* AI Inference Engine mengalami kecelakaan (*crash*) atau proses inferensi melebihi latensi maksimum 3.0 detik[cite: 1].
  * 1. On langkah 5 atau 6, sistem tidak menerima respons dari AI Inference Engine dalam waktu 3.0 detik[cite: 1].
  * 2. Sistem mencatat log *error connection/timeout*.
  * 3. Sistem menampilkan notifikasi *banner*: *"Layanan prediksi AI sedang lambat/tidak merespons. Menampilkan estimasi berdasarkan metode cadangan."*
  * 4. Sistem menjalankan algoritma *fallback* (*Moving Average 3 Bulanan*) secara lokal di backend untuk menampilkan hasil sementara tanpa menghentikan aplikasi (*Graceful Degradation*)[cite: 1].

* **EX-03: Skor Keyakinan Model Rendah / Variance Tinggi (Low Confidence / High Anomaly)**
  * *Kondisi:* Fluktuasi data historis sangat ekstrem sehingga estimasi persentase eror model diproyeksikan melebihi ambang batas ($\text{SMAPE} > 25\%$)[cite: 1].
  * 1. On langkah 7, AI Inference Engine mengembalikan hasil prediksi beserta bendera (*flag*) `low_confidence = True`[cite: 1].
  * 2. Sistem tetap menampilkan hasil peramalan kuantitas di layar[cite: 1].
  * 3. Sistem menampilkan tanda peringatan (*warning badge*): *"Tingkat variabilitas data sangat tinggi. Hasil peramalan memiliki tingkat ketidakpastian tinggi."*[cite: 1]
  * 4. Sistem menyarankan pengguna untuk memanfaatkan fitur *Manual Override* (US-09)[cite: 1].

## 2. UC-02: Melakukan Validasi dan Preprocessing Data Transaksi CSV

* **ID & Nama Use Case:** UC-02 Melakukan Validasi dan Preprocessing Data Transaksi CSV
* **Aktor Utama:** Staf Gudang / Manager Persediaan[cite: 1]
* **Aktor Pendukung:** Database System (PostgreSQL)
* **Kaitan ke ID User Story & FR:** US-01, US-02 | FR-01, FR-02[cite: 1]

### Preconditions
Pengguna memiliki berkas CSV data penjualan suku cadang bulanan[cite: 1].

### Postconditions
Data transaksi tervalidasi, nilai *missing/zero* ditangani, dan tersimpan di database siap pakai[cite: 1].

### Alur Utama (Main Flow)
1. Staf Gudang memilih dan mengunggah berkas CSV ke dalam sistem[cite: 1].
2. Sistem memeriksa format berkas, nama kolom wajib, dan tipe data.
3. Sistem mendeteksi periode bulan yang kosong (*zero demand*) dan melakukan *zero-imputation* (mengisi nilai `0`)[cite: 1].
4. Sistem menyimpan data transaksi terstruktur ke dalam Database.
5. Sistem menampilkan konfirmasi sukses beserta ringkasan baris data yang berhasil diimpor[cite: 1].

### Alur Eksepsi
* **EX-01: Struktur Berkas CSV Salah / Rusak**
  * 1. On langkah 2, sistem mendeteksi kolom wajib (misal: `item_code` atau `qty`) tidak ditemukan[cite: 1].
  * 2. Sistem membatalkan proses impor.
  * 3. Sistem menampilkan daftar rincian baris/kolom yang *invalid* agar diandalkan pengguna[cite: 1].
